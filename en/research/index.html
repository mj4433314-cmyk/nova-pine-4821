What is the problem?

Take words of zeros and ones, each n positions long with exactly w ones. How many words can you collect at most, if any two of them must differ in at least d positions? That number is written A(n,d,w).

These numbers are basic to coding theory and error correction, and most of their exact values are still unknown. Each cell has a lower bound, the largest code anyone has found, and an upper bound that cannot be passed. Everything on this page raises a lower bound.

Check it yourself

Each file is plain text, one word per line. Check three things: every line has length n, every line has w ones, and any two lines differ in at least d positions. The parameters and the word count are in the file name, as in A_46_8_8_9704.txt.

A short program that checks any file (the large ones take minutes):

# python3 check.py A_46_8_8_9704.txt
import itertools, os, re, sys
f = sys.argv[1]
n, d, w, size = map(int, re.findall(r"\d+", os.path.basename(f))[-4:])
words = [l.strip() for l in open(f) if l.strip()]
assert len(words) == size == len(set(words))
assert all(len(x) == n and x.count("1") == w and set(x) <= {"0", "1"} for x in words)
v = [int(x, 2) for x in words]
m = min(bin(a ^ b).count("1") for a, b in itertools.combinations(v, 2))
print(size, "words, smallest distance", m, "OK" if m >= d else "FAIL")

Before publication every file passed two independent checkers: the first measures the difference between every two words, the second makes sure no w − d/2 + 1 positions are all ones in two different words.

Plainly

  • These are new record lower bounds, not complete solutions: the exact value of every cell is still an open problem.
  • The world table is the reference. If a number there changes after 22 November 2026, trust the table over this page: aeb.win.tue.nl/codes/Andw.html.
